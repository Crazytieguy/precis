# add-fixture

Adding a fixture has six steps. The North Star is drafted by a dedicated
agent; the regression baselines are generated by running `cargo t` with an
env var. No alignment-reviewer in the loop — the divergence metric is
deterministic, lives under `cargo t`, and produces committed markdown
reports you can `git diff`.

Pass only the fixture name (e.g. `thiserror`) through the flow. Paths and
agent spawn strings are derived from it.

**Defaults**: the flow runs end-to-end without stopping. If the invocation
explicitly asks for a human checkpoint on the NS ("let me review the
north star first"), pause at step 4; otherwise proceed through.

**Idempotency**: skip steps whose output already exists.

- `tests/fixtures/<name>/` exists → skip step 1's clone.
- `tests/north-stars/<name>.toml` exists → skip steps 2–4.
- `<name>` is already in the per-fixture-test macro list in
  `tests/schedule_order.rs` → skip step 5.
- Baselines regenerate via `UPDATE_BASELINES=1 cargo t` — idempotent by
  construction.

## 1. Declare and clone the repo

Check `tests/data/fixtures.rs` — the shared list of all fixture repos.

- **Already declared?** Skip to step 2.
- **Not declared?** Add a `("<name>", "<git-url>", "<commit-sha>")` line under the language section. The commit SHA pins the revision.

Then:

```bash
cargo run --bin clone_fixtures
```

Clones any missing fixtures to `tests/fixtures/<name>/` (strips `.git`,
writes `.precis-pin`). Already-cloned fixtures are skipped.

## 2. Spawn three NS author drafts in parallel

Each draft is independent. Three drafts produce materially different
rankings the combiner merges — one draft alone is too brittle.

Spawn three `north-star-author` agents **in parallel** (single message,
three tool calls). Each gets:

- Fixture root: `tests/fixtures/<name>/`
- Output path: `tests/north-stars/drafts/<name>__{1,2,3}.toml` (different
  suffix per draft so they don't collide)
- Fixture's revision pin: the SHA from `tests/data/fixtures.rs` (also in
  `tests/fixtures/<name>/.precis-pin`)
- Instruction to iterate using `cargo run --bin validate-ns -- <path>`
  until output is violation-free

Drafts take 10–20 minutes each; in parallel they finish together.

## 3. Combine drafts

Spawn one `north-star-combiner` agent with just the fixture name. It
reads all three drafts from `tests/north-stars/drafts/<name>__*.toml`,
synthesizes them into one coherent ranking, runs validate-ns, and
writes `tests/north-stars/<name>.toml`.

## 4. Freeze (optional human review)

The combined NS is the **frozen** reference. From this point don't edit
`tests/north-stars/<name>.toml` — amendments need explicit rationale per
`docs/design-notes.md`.

If the user asked to review before proceeding: stop here, show the file
path. Otherwise: continue. Drafts stay in place as combiner provenance.

## 5. Register in the test macro

Edit `tests/schedule_order.rs` — add a `per_fixture_tests!(<name>);` line
alongside the existing fixtures. This generates 9 test fns per fixture
(4 schedule-TOML regressions + 4 divergence regressions + 1 rendered
snapshot at 3000). The `ns_pins_match_fixture_pins` test picks up the
new NS automatically.

## 6. Generate baselines

```bash
UPDATE_BASELINES=1 cargo t
```

Produces all baselines in one invocation:

- `tests/snapshots/schedule/<name>__{1500,3000,6000,10000}.toml`
- `tests/divergence/<name>__{1500,3000,6000,10000}.md` (only when an NS
  exists for the fixture)
- `tests/snapshots/rendered/<name>__3000.snap`

Score lines print to stdout (`<fixture>__<budget>: Sim=… OffScript=…
Pred=… Coverage=…`) for fast eyeballing. `git diff tests/divergence/`
shows the per-batch story.

## 7. Iterate (or report back)

Read the divergence reports. Tune walker/value if the missed-NS-batches
list points at concrete content the walker isn't hitting.

**Pursue general solutions.** Every change should improve the walker
across the general distribution of real-world codebases — fixtures are
samples, not targets. Prefer an accepted divergence to a
fixture-specific heuristic.

After a walker change, `UPDATE_BASELINES=1 cargo t` regenerates every
baseline. `git diff tests/divergence/` shows what got better and what
got worse at a glance. Run `/simplify` after non-trivial walker changes.

**When stuck.** A divergence that resists general fixes is a sign to
consult more perspectives. Spawn an Agent for independent brainstorming
and/or run `codex-companion adversarial-review` for a second opinion.
Report back only as a last resort.

Stop iterating when:

- All divergence reports read as "remaining gaps are legitimate NS
  content the walker can't cheaply deliver at this budget", **or**
- The remaining gaps need schema / NS changes the user should approve.

## Things to *not* do

- Don't hand-write NSs. They're large and the agent produces better
  ones than a direct draft.
- Don't edit a frozen NS without the amendment protocol.
- Don't skip the combiner — three drafts without synthesis produces
  three different rankings, not consensus.
- Don't commit `.new` sidecars (gitignored by default; CI guards).
- Don't run `cargo run --bin compare-ns` — it doesn't exist; the
  metric lives in the `cargo t` flow.
